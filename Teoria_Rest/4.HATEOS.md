## HATEOS

HATEOAS = Hypermedia As The Engine Of Application State (Hipermídia como o Mecanismo/Motor do Estado da Aplicação).

Forma de organizar a API - dentro da maturidade de Richardson

- Guia o cliente sobre quais ações ele pode ou não executar a seguir, dependendo do estado atual do recurso:

## Analogia simples (A Web / Navegador):

Quando você entra num site de e-commerce, você não precisa decorar a URL de fechamento do pedido (/checkout/pagar). Você simplesmente clica nos botões/links que a página te oferece. Se um produto está esgotado, o botão "Comprar" nem aparece.

Com HATEOAS, a API faz a mesma coisa para o cliente (seja frontend, app mobile ou outro microsserviço).

O cliente não precisa deixar URLs "chumbadas" (hardcoded) no código. Se o estado de um pedido mudar de PENDENTE para PAGO, a própria resposta da API remove o link de pagar e disponibiliza o de emitir-nota ou rastrear-entrega.

```json
Response 'pura':
{
  "id": 105,
  "status": "PENDENTE",
  "valor": 150.00
}
```

```json
Reponse formatada com HATEOS (padrão HAL):
{
  "id": 105,
  "status": "PENDENTE",
  "valor": 150.00,
  "_links": {
    "self": { "href": "https://api.exemplo.com/pedidos/105" },
    "pagamento": { "href": "https://api.exemplo.com/pedidos/105/pagamento" },
    "cancelar": { "href": "https://api.exemplo.com/pedidos/105/cancelamento" }
  }
}

```

### HATEOAS (Hypermedia As The Engine Of Application State)

- **Definição:** Nível 3 (máximo) do Modelo de Maturidade de Richardson. É o princípio segundo o qual uma API REST retorna não apenas a representação do recurso (dados), mas também controles de hipermídia (links dinâmicos) que ensinam o cliente a navegar e executar as próximas ações válidas.
- **Propósito Principal:** Funcionar como um "motor de estados", onde as ações disponíveis dependem do estado atual daquele recurso, desacoplando o cliente de URLs fixas (_hardcoded_).
- **Estrutura Básica:**
    - **Payload:** Atributos do recurso requisitado (ex: `id`, `nome`, `status`).
    - **Links (`_links`):** Relações de hipermídia (ex: `self`, `atualizar`, `excluir`, `pagar`).
- **Vantagens:** Alto desacoplamento entre cliente e servidor, descoberta dinâmica de rotas e regras de negócio refletidas diretamente na navegação.
- **Desvantagens/Custos:** Maior complexidade de implementação no backend e payload de resposta mais pesado.
